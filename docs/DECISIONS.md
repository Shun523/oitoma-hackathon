# 実装中の小さな判断（1行ずつ）

- 段階0: vitest 5 が @types/node ^22以上を要求するため、雛形既定の ^20 から ^22 に上げた。
- 段階0: AGENTS.md の参照先は実在ファイルに合わせ docs/spec.md（小文字）とし、docs/SPEC.md（仕様書の表記）は作らなかった。
- 段階0: 雛形の .gitignore（.env*）では .env.example が無視されるため、!.env.example を足してひな形だけコミットできるようにした。
- 段階1: NG語リストの持ち方は `export const NG_WORDS: string[]` とし、仕様の語順のまま並べた。
- 段階1: `computeMetrics` は引数を `Record<string, Assignment>` 1つにし、人数・タグ人数・要確認まで中で数える形にした。
- 段階2: ダミー回答の型は `SampleAnswer{name,affiliation,category,intro,hobby,consent}` とし、区分はForms記入文言のまま持たせた。
- 段階2: 区分判定が字面一致のため、学生の文言は「学部生」でなく「学生」「大学院学生」にした（「学部生」は「学生」を含まない）。
- 段階2: 6人未満・300人超えは `toParticipants` が日本語メッセージの Error を投げ、画面側で表示する形にした。
- 段階2: sample-200は種20261009の乱数で組み合わせ、同意なしは約5%（11人）になるようにした。
- 段階3: Next.js 16（cacheComponents有効）ではrouteの `dynamic = 'force-dynamic'` が建てられないため削除し、Requestを使うroute handlerは要求時実行のままとした。
- 段階3: タグ12文字の判定は `displayLength`（半角0.5文字）、話題15文字は文字数で判定した。
- 段階3: `/api/health?ping=1` のlive確認はおいとまの `/models` を1回呼ぶ形にした。
- 段階4: 続きからは参加者数が同じなら前回のparamsを使い、違うなら決め直す。
- 段階4: 公開用データの組み立ては run-pipeline.ts に仮置きし、段階7で publish.ts に移す。
- 段階5: admin配下は `instant = false`＋`connection()`で要求時描画にした（Cache Componentsではdynamicが使えないため）。
- 段階5: `/admin`はサーバredirectがpostponed描画で誤作動したためクライアント置換にした。
- 段階5: StickerSet.tsxは構成図にないが本文の参照に合わせ作った。
- 段階5: 保存失敗時のsaveError通知はpersist書込と循環しないようguardした。
- 段階5: スクリプトはCJS扱いでも動くようトップレベルawaitを使わない（check-llmも修正）。
- 段階5: TagInputはIMEのため入力中は制限せず超過を赤表示し確定時に弾く。
- 段階6: 用紙の行ではStickerSetを常に横1行にする（direction="row"）。
- 段階6: すき間X・Yの刻みは位置と同じ0.5mmにした。
- 直し: 人の指示でアプリ名を `#おいとま活用中` に変更し、仕様書の3か所も合わせた。
